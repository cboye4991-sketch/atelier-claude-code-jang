# Decisions

One entry per decision: date, choice, reason.

## 2026-10-01 — Initial build

**What**
- Phase 1 single-page app: Vite + React 19 + TypeScript strict, no router (two tabs held in state), no UI library.
- « Exercices »: catalogue of the 14 exercises (`JNG-PC-01` to `JNG-PC-14`), text search, Chimie / Physique filter,
  disabled « Corriger avec Jàng » button (« Bientôt : correction en direct (phase 2) »).
- « Mon carnet »: status per exercise (À faire / Essayé / Réussi / À revoir), private note (280 characters),
  counters per chapter, overall progress line, reset with an in-page confirmation (no `window.confirm`).
- `src/data/exercises.ts` is generated by `scripts/generate-exercises.mjs` from `../jang-source/jang_exercices_pc_ts2.csv`.
  Only a whitelist of columns is read: ID, Matiere, Chapitre, Enonce, Donnees, Statut_validation.
- The notebook goes through `src/lib/repository.ts` (async `NotebookRepository` interface). The localStorage
  implementation falls back to memory when storage is blocked, full or corrupted, and the UI then warns the student.
- Brand tokens from `/jang-brand` in `src/styles/tokens.css`; squared-paper background in pure CSS, no image.

**Why**
- The knowledge base is the single source of truth for IDs and statements, so the catalogue is generated, not retyped.
- An async repository interface lets Firestore or Supabase replace localStorage later without touching the UI.
- Tabs in state keep the bundle small (about 77 KB gzipped JS + CSS, measured on this build) for students on a small data bundle.
- The subject is derived from the chapter prefix because `Matiere` is « Physique-Chimie » for every row.
- The correction red `#D2382A` is not used: phase 1 shows no correction. « À revoir » uses ink, not red.

**Why the reference answers are excluded**
- The CSV also holds `Corrige_reference`, `Resultat_final`, `Erreur_frequente`, `Exercice_similaire` and `Reponse_similaire`.
  Anything in the repo or the bundle can be read by any student with the browser dev tools, so shipping them
  would show the solutions and bypass the corrector. The answers stay in the knowledge base (Dify `Jang_KB_v1`)
  and will only be reached through the server-side workflow in phase 2.
- Two guards: the generator uses a column whitelist (never copies a whole row), and `scripts/check-no-answers.mjs`
  compares every answer fragment of the CSV against `src/` and `dist/`. It runs at the end of `npm run build`
  and fails the build on a leak. It was checked against a planted leak.
- The status label never claims a validation that is not recorded: anything not starting with « Validé » shows
  « Corrigé à valider par un professeur ».

**Trade-offs**
- Three Google Fonts families (Schibsted Grotesk 800, Atkinson Hyperlegible 400/700, IBM Plex Mono 500) instead of
  the « one subset font » rule in CLAUDE.md. Requested for the brand; cost is extra font requests on first load,
  softened by `display=swap`, `preconnect` and system fallbacks. The fonts are not measured here: check them before
  promising a data figure. The rule in CLAUDE.md was updated accordingly.
- The generated `exercises.ts` is committed, so a build does not need the CSV. Run `npm run gen:exercises`
  after the knowledge base changes. `check:answers` is skipped (with a warning) when the CSV is absent.
- localStorage is per browser and per device: the notebook is not synced, and clearing site data erases it.
  Notes are private but stored in clear text on the device.
- Search is a simple accent-insensitive substring match over 14 items; no index is needed at this size.
- Not tested in a real browser in this session (no browser permission): behaviour is covered by jsdom tests,
  including a remount that simulates a refresh. Check 360 px rendering by hand.

## 2026-10-01 — Notebook export

**What**
- « Mon carnet » has an « Exporter mon carnet » button that downloads `jang-carnet-AAAA-MM-JJ.json` (local date).
- The file holds `exportedAt` (ISO) and, for all 14 exercises in catalogue order: `id`, `chapter`, `status`, `note`.
- Logic lives in `src/lib/notebook-export.ts`; the button is disabled while the notebook is empty, like the reset.

**Why**
- The notebook only lives in one browser: a file gives the student a copy to keep or show a teacher.
- Entries are built field by field from public data (ID, chapter) and the notebook, so no statement, validation
  or reference answer can reach the file. A test checks the keys and that no statement appears in the JSON.
- `status` is the stable code (`todo`, `tried`, `solved`, `review`), not the French label, so the format survives UI rewording.
- The download is local (Blob + temporary link): no request, no extra dependency, no data cost.
